# Zone Diet Application

크로스핏 존다 8주 프로그램용 팀 관리 앱입니다. 회원 20명, 관리자 1명, 기본 5개 팀으로 시작합니다.

온라인 데모: https://zone-diet-application.vercel.app

## 실행

Node.js 24 LTS를 사용합니다.

```sh
npm ci
npm start
```

로컬 주소는 http://localhost:3000 입니다. 로컬 개발 데이터는 `.data/`에 저장됩니다. 기존 단일 사진 기록도 그대로 사용할 수 있습니다.

## 주요 기능

- 관리자 팀 편성 및 식단·조장·미션운동·SNS·기타 역할 지정
- 회원별 로그인과 개인 체중·운동 기록
- 아침·점심·저녁마다 사진 최대 6장, 추가·제거 및 확대 갤러리
- 끼니별 탄수화물·단백질·지방 블록 입력 및 하루 합계 (미입력과 0 구분)
- 본인의 저장된 하루 식단으로 카페 글 제목·사진 포함 본문 생성
- 제목/본문 텍스트 복사, 사진을 내장한 HTML 파일 저장
- 회원 본인의 네이버 로그인 연결, 관리자 게시판 지정 및 계정 승인
- 게시 대상과 사진 포함 본문을 확인한 뒤 네이버 카페에 게시 (개발자 앱 설정 필요)
- 날짜별 중복 게시 방지, 응답이 불확실한 게시 건의 관리자 확인
- 같은 팀의 식단 사진 확인
- 현재 식단 담당자만 날짜별 사진 모음을 전체 회원에게 공유
- 공유 시점의 사진 보존, 명시적인 재공유로 갱신
- 로그인·팀·역할 검사, 변경 버전 검사, 충돌 시 덮어쓰기 방지

## Vercel 배포

GitHub의 `Jung-won-seok/Zone_Diet_Application` 저장소와 Vercel의 `zone-diet-application` 프로젝트가 연결되어 있습니다. `main` 브랜치에 푸시하면 프로덕션 자동 배포가 실행됩니다. 배포 결과는 Vercel 프로젝트의 Deployments에서 확인할 수 있습니다.

`vercel.json`은 정적 화면과 Node.js API를 함께 배포합니다. 서버리스 실행 환경에서 로컬 파일 시스템에 기록을 저장하지 않습니다.

1. Vercel 프로젝트에 **Private Vercel Blob** 저장소를 연결합니다.
2. `BLOB_READ_WRITE_TOKEN`과 `INITIAL_ACCOUNT_PASSWORDS`를 Production 환경변수에 설정합니다. `.env.example`에서 키 형식을 확인할 수 있습니다.
3. `INITIAL_ACCOUNT_PASSWORDS`는 `admin`, `member01`부터 `member20`까지 8자 이상의 비밀번호를 담은 JSON입니다. 데모에서는 간단한 비밀번호를 사용할 수 있으며, 실제 운영 시에는 계정별로 강한 비밀번호를 사용하세요. 비밀번호를 저장소에 커밋하지 마세요.
4. 배포하면 빈 저장소에 가상의 회원 20명과 관리자 계정이 초기화됩니다. 초기화 이후 환경변수 변경만으로 기존 비밀번호가 변경되지는 않습니다.

온라인 사진·회원정보·세션은 비공개 Blob에 저장합니다. 요청마다 최신 상태를 읽고 ETag 조건부 쓰기로 동시 변경을 확인합니다. 사진은 앱의 로그인과 공개 범위를 확인한 뒤에만 제공합니다. 로컬 `.data/`나 계정 안내 파일은 배포 및 Git 대상에서 제외됩니다.

전체 상태를 하나의 문서로 저장하므로 동시에 저장하면 재시도가 필요할 수 있습니다. 현재 20명 규모의 시범 운영을 위한 구성입니다. 본격 운영 전 회원 가입·비밀번호 변경/복구, 데이터 보존·삭제 정책을 추가해야 합니다.

## 네이버 카페 연결 설정

네이버 개발자 앱의 키가 없으면 설정 화면과 미리보기는 사용할 수 있지만 실제 계정 연결과 게시는 비활성화됩니다. 기본 카페는 `https://cafe.naver.com/mycaffelatte` (카페 ID `31811778`)입니다. 예시 게시판 ID `7`은 특정 회원에게 자동 배정하지 않습니다.

1. [네이버 개발자 센터](https://developers.naver.com/apps/#/register)에서 애플리케이션을 등록하고 **네이버 로그인** 및 **카페 가입·글쓰기** 권한을 설정합니다. 표시용 별명/이름은 선택 동의 항목으로 사용할 수 있습니다. 회원 식별에는 이름이 아닌 네이버 고유 식별자를 사용합니다.
2. 웹 서비스 URL은 `https://zone-diet-application.vercel.app`, Callback URL은 `https://zone-diet-application.vercel.app/api/naver/callback`으로 등록합니다.
3. Vercel 프로젝트 Settings → Environment Variables의 Production에 다음 값을 설정한 뒤 재배포합니다. Secret과 암호화 키를 GitHub, 브라우저 코드, 채팅에 넣지 마세요.

| 환경변수 | 값 |
| --- | --- |
| `NAVER_CLIENT_ID` | 네이버 개발자 앱의 Client ID |
| `NAVER_CLIENT_SECRET` | 같은 앱의 Client Secret |
| `NAVER_CALLBACK_URL` | 위 Production Callback URL |
| `NAVER_TOKEN_ENCRYPTION_KEY` | 무작위 32바이트를 Base64로 인코딩한 값 |

암호화 키는 서버에 저장하는 네이버 토큰 보호용입니다. 비밀번호 관리자 등에서 안전하게 보관하고 연결된 계정이 있는 동안 변경하지 마세요. 키를 변경하면 기존 회원의 재연결이 필요합니다. 키는 `node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64'))"`로 생성할 수 있습니다.

로컬에서는 기존 `.env.local`에 위 네 가지 설정을 추가합니다. 로컬 Callback URL은 `http://localhost:3000/api/naver/callback`이고 네이버 개발자 센터에도 따로 등록해야 합니다. `npm start`가 `.env.local`을 읽습니다. 기존 파일에 있는 다른 설정을 지우거나 운영 환경변수 전체를 로컬로 복사하지 마세요.

개발 중에는 개발자 센터의 테스트 ID를 등록하여 이용하고, 실제 회원 대상 운영 전에 [네이버 로그인 검수 안내](https://developers.naver.com/docs/login/verify/verify.md)를 확인하세요. 해당 회원은 카페 가입과 대상 게시판의 글쓰기 권한을 갖고 있어야 합니다. API 계약은 [공식 카페 API 문서](https://developers.naver.com/docs/login/cafe-api/cafe-api.md)를 따릅니다.

### 실제 이용 순서

1. 회원이 앱 로그인 → 내 설정 → 네이버 계정 연결에서 본인의 네이버 계정으로 인증합니다.
2. 관리자가 네이버 카페 연결 화면에서 앱 회원과 연결된 네이버 이름을 확인하고, 각 회원의 게시판 ID/이름을 지정하여 연결을 승인합니다. 게시판 링크를 붙여 넣으면 ID를 추출할 수 있습니다. 이름이 같아도 자동으로 연결하지 않습니다.
3. 회원이 저장한 하루 식단의 카페 글 미리보기를 열고 제목, 사진, 블록 합계와 게시 대상을 확인한 뒤 직접 게시합니다. 기본 공개 설정은 카페 회원 공개, 검색 비공개입니다.
4. 성공하면 게시글 링크를 저장합니다. 같은 프로그램·회원·날짜는 다시 게시하지 않습니다. 게시 후 수정은 카페에서 처리합니다.

네이버 계정을 다시 연결하면 관리자 승인이 새로 필요합니다. 네이버 비밀번호는 앱에서 입력받거나 저장하지 않습니다. 토큰은 서버에서 암호화해 보관하며 다른 회원이나 관리자에게 반환하지 않습니다.

네이버 응답이 끊기거나 결과 저장에 실패하면 중복 글을 막기 위해 자동 재시도하지 않습니다. 관리자가 실제 카페를 확인한 뒤 게시글 주소를 등록하거나, 글이 없는 것을 확인하여 재시도를 허용할 수 있습니다. 진행 중인 요청은 최소 2분이 지나야 수동 처리할 수 있습니다. 외부 인증/게시 계약은 모의 응답으로 검증했으며, 실제 키와 카페 권한을 설정한 후 실계정 확인이 필요합니다.
